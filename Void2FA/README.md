# Void2FA

Двухфакторная аутентификация (2FA) для **Paper 26.2** через **Telegram-бота**.

Поддерживаются два транспорта: оригинальный **embedded** (Telegram-клиент внутри
плагина) и **external** — отдельный Python-бот на твоей инфраструктуре через
аутентифицированный мост. Используй только один транспорт для токена.

**Новое в 1.3.5 + бот 1.4.0:** задержка от нажатия в Telegram до входа снижена до ~1-2 с.
Раньше три независимых таймера складывались: плагин ждал до 1 с перед отправкой, бот до 1 с перед
доставкой в Telegram и ещё до 1 с перед следующим опросом. Теперь исходящее событие будит цикл
сразу, бот доставляет по сигналу от `/v1/sync`, а пока игрок ждёт подтверждения, обмен идёт каждые
250 мс (`active-poll-interval-ms`) вместо 1000 мс. В простое нагрузка не выросла.
**Нужно обновить обе стороны** —протокол тот же (v1), но ускорение даёт именно пара.

**Новое в 1.3.4 (только плагин):** убраны ложные сообщения «Bridge недоступен» при живом боте.
Раньше любой отказ разбора ответа — неверная подпись, расхождение часов, другой формат, HTTP 401 —
писался как обрыв сети и сразу гасил 2FA. Теперь такие случаи называются своим именем
(`bad-signature`, `clock-skew`, `http-401`, `username`, `protocol`), готовность не сбрасывается,
а единичный сетевой сбой терпится: авария объявляется только с 3 неудач подряд.

**Новое в 1.3.3 (только плагин, бот обновлять не нужно):** исправлена ложная недоступность моста.
Окно готовности было жёстко 15 с, а запрос ждал ответа до 20 с — при медленном ответе Bothost плагин
считал бота недоступным, даже когда тот работал, и 2FA молча не срабатывала. Теперь таймауты настраиваются
(`telegram.bridge.timeout-seconds`, `connect-timeout-seconds`, `ready-grace-seconds`), а окно готовности
по умолчанию больше таймаута запроса. Протокол v1 не изменился — работает с уже задеплоенным ботом.

**Новое в 1.3.2:** `/help` и `/start` в Telegram теперь всегда показывают полный список команд,
а бот сам публикует меню команд в Telegram (кнопка «Меню» рядом с полем ввода).
Если в локальном `config.yml` остался старый текст `tg-help`/`tg-start`, недостающие команды
дописываются автоматически — игроки узнают про `/kick` и `/revoke` без правки конфига.

**Новое в 1.3.0:** в Telegram появились `/kick` и `/revoke`.
`/kick` завершает текущий вход и сбрасывает короткую сессию, но сохраняет доверенные устройства.
`/revoke` удаляет все доверенные устройства, сбрасывает сессию и кикает игрока, если он онлайн; `/untrust all` делает то же самое.
Подтверждения входа и сообщения о доверенных устройствах уходят только в Telegram:
в игровом чате больше не выводятся ID устройства и IP, список/удаление устройств для игрока тоже приходят в Telegram.

**Новое в 1.2.0:** доверенные устройства и блокировка аккаунта.
После подтверждения входа устройство (IP) запоминается: следующие входы с него проходят без кода,
а другие IP требуют 2FA. Команды: `/2fa trust`, `/2fa devices`, `/2fa untrust <id|all>`,
`/2fa lock`, `/2fa unlock`; в Telegram: `/lock`, `/unlock`, `/devices`, `/untrust <id|all>`.
Пока аккаунт заблокирован, войти нельзя никому (даже с доверенного устройства и с `void2fa.bypass`).

**Новое в 1.1.0:** [отдельный бот и развёртывание](BOT_DEPLOY.md), [протокол моста](BRIDGE_PROTOCOL.md).
Старый `release/Void2FA-1.0.0.jar` не поддерживает external; новый JAR собирается из исходников.

📌 **Для подключения бота позже:** [сохранённая инструкция, тексты BotFather,
сообщения и ТЗ отдельного бота](BOT_SETUP.md). Подключение сейчас не требуется.

## Возможности

- 🔐 Подтверждение входа через Telegram: **одноразовый код** и/или **кнопки** «✅ Подтвердить / ❌ Отклонить».
- 🧊 Заморозка до подтверждения: нельзя двигаться, писать в чат, использовать команды (кроме auth-команд), ломать/ставить блоки, взаимодействовать, выбрасывать предметы, кликать в инвентаре, телепортироваться; урон не проходит. Накладывается слепота.
- 🔗 Привязка аккаунта через одноразовый токен (`/2fa link` → боту `/link <код>` или ссылка `t.me/...?start=LINK_...`).
- ⏱️ Таймаут входа, лимит попыток, срок действия кода — всё настраивается.
- 🕹️ Два режима: `opt-in` (по желанию) и `required` (для всех).
- 🧠 «Сессии»: можно не спрашивать 2FA повторно при входе с того же IP в течение N минут.
- 📱 Доверенные устройства: подтвердил вход один раз — этот IP запоминается и дальше пускает без кода. Уведомления только в Telegram.
- 🔒 Блокировка аккаунта: `/2fa lock` или `/lock` в Telegram; пока не разблокируешь — никто не войдёт.
- 🛡️ Право `void2fa.bypass` для доверенных игроков/админов.
- 🗣️ Все сообщения на русском и полностью настраиваются в `config.yml`.
- 📦 Без внешних зависимостей (собственный JSON-парсер, `java.net.http`).

## Быстрый старт: встроенный транспорт (embedded)

Для отдельного бота используй [BOT_DEPLOY.md](BOT_DEPLOY.md), не шаги ниже.

1. Положи `Void2FA-1.3.5.jar` (собирается из исходников или берётся из артефакта CI `Void2FA-plugin`) в папку `plugins/` сервера.
2. Запусти сервер — создастся `plugins/Void2FA/config.yml`.
3. Создай бота: напиши [@BotFather](https://t.me/BotFather) → `/newbot` → получи **токен**.
4. Вставь токен в `config.yml`:
   ```yaml
   telegram:
     bot-token: "123456789:AAEx..."
   ```
5. Выполни в игре `/2faadmin reload` (или перезапусти сервер). В консоли появится
   «Telegram-бот подключён: @имя_бота».
6. Привяжи аккаунт: в игре `/2fa link` → открой бота и отправь `/link <код>`
   (или перейди по ссылке из сообщения).
7. Готово! При следующем входе бот пришлёт код и кнопки подтверждения.

> Пока `bot-token` пустой, плагин работает вхолостую и никого не блокирует —
> можно спокойно настроить всё заранее.

## Команды

| Команда | Описание |
|---|---|
| `/2fa` | Статус 2FA |
| `/2fa link` | Привязать Telegram |
| `/2fa unlink` | Отвязать Telegram |
| `/2fa on` / `/2fa off` | Включить / выключить 2FA |
| `/2fa code <код>` | Подтвердить вход кодом |
| `/2fa resend` | Выслать код повторно |
| `/2fa help` | Помощь |
| `/2fa lock` | Заблокировать аккаунт (никто не войдёт) |
| `/2fa unlock` | Разблокировать аккаунт |
| `/2fa trust` | Запомнить текущее устройство/IP |
| `/2fa devices` | Список доверенных устройств (ответ в Telegram) |
| `/2fa untrust <id\|all>` | Убрать устройство; `all` отзывает все устройства, сбрасывает сессию и кикает |
| `/login <код>` | Быстрый ввод кода (алиас `/2fa code`) |
| `/2faadmin reload` | Перезагрузить конфиг и перезапустить бота |
| `/2faadmin status <игрок>` | Статус игрока |
| `/2faadmin reset <игрок>` | Сбросить привязку игрока |
| `/2faadmin enable <игрок>` | Включить 2FA игроку |
| `/2faadmin disable <игрок>` | Выключить 2FA игроку |
| `/2faadmin lock <игрок>` | Заблокировать аккаунт игрока |
| `/2faadmin unlock <игрок>` | Разблокировать аккаунт игрока |
| `/2faadmin devices <игрок>` | Доверенные устройства игрока |
| `/2faadmin untrust <игрок> <id\|all>` | Убрать устройство игрока; `all` также сбрасывает сессию и кикает |

Алиасы: `/2fa` → `/tfa`, `/twofa`; `/2faadmin` → `/tfaadmin`.

### Команды бота (в Telegram)

| Команда | Описание |
|---|---|
| `/start` | Приветствие и полный список команд |
| `/link <код>` | Привязать аккаунт (код из игры) |
| `/status` | Статус привязки |
| `/unlink` | Отвязать аккаунт |
| `/help` | Полный список команд бота |
| `/lock` | Заблокировать аккаунт |
| `/unlock` | Разблокировать аккаунт |
| `/devices` | Доверенные устройства |
| `/untrust <id\|all>` | Убрать устройство; `all` = полный отзыв доступа и кик |
| `/kick` | Завершить текущий вход и сбросить короткую сессию, устройства сохранить |
| `/revoke` | Удалить все доверенные устройства, сбросить сессию и кикнуть |

## Права (permissions)

| Право | По умолчанию | Описание |
|---|---|---|
| `void2fa.use` | все | Использование `/2fa` и `/login` |
| `void2fa.admin` | OP | Админ-команды `/2faadmin` |
| `void2fa.bypass` | нет | Полный пропуск 2FA |

## Как это работает

1. Игрок заходит → если у него включена 2FA (или режим `required`), он замораживается.
2. Плагин шлёт в его Telegram одноразовый код и кнопки «Подтвердить / Отклонить».
3. Игрок либо вводит код в игре (`/login <код>` или просто числом в чат), либо жмёт кнопку в боте.
4. При успехе — разморозка; при отказе, таймауте или превышении попыток — кик.

Привязка хранится в `plugins/Void2FA/data.yml` (UUID ↔ Telegram ID).

## Конфигурация

Основные параметры (`config.yml` → `settings`):

| Параметр | По умолчанию | Описание |
|---|---|---|
| `mode` | `opt-in` | `opt-in` / `required` |
| `code-length` | `6` | Длина кода |
| `code-ttl-seconds` | `120` | Срок действия кода |
| `auth-timeout-seconds` | `90` | Время на подтверждение (потом кик) |
| `max-attempts` | `5` | Лимит неверных попыток |
| `session-minutes` | `0` | Не спрашивать 2FA повторно с того же IP N минут |
| `freeze` | `true` | Заморозка до подтверждения |
| `blindness` | `true` | Слепота до подтверждения |
| `lockdown-if-unavailable` | `false` | Не пускать никого, если бот недоступен |
| `trusted-devices.enabled` | `true` | Доверенные устройства |
| `trusted-devices.remember-on-approve` | `true` | Запоминать IP после подтверждения входа |
| `trusted-devices.max-devices` | `5` | Лимит устройств на игрока |
| `trusted-devices.ttl-days` | `0` | Срок доверия в днях, 0 = бессрочно |
| `account-lock.enabled` | `true` | Команды блокировки аккаунта |

`/help` и `/start` дополняются недостающими командами автоматически, даже если в локальном конфиге
старый текст. Меню команд в Telegram бот публикует сам при запуске (`setMyCommands`); вручную
оформлять его через BotFather не нужно, но можно — тексты ниже совпадают.

При обновлении со старой версии новые сообщения подставляются из JAR автоматически, но уже изменённые
тобой строки `help-player`, `help-admin`, `status-self`, `admin-status`, `tg-start`, `tg-help`, `tg-status-linked`
останутся старыми. Чтобы появилось меню новых команд, скопируй эти строки из свежего `config.yml` или удали их из локального конфига.

Все сообщения (в игре, на экране кика и в Telegram) настраиваются в секции
`messages`. Цвета — через `&`. Плейсхолдеры: `{player}`, `{code}`, `{ip}`,
`{attempts}`, `{token}`, `{bot}`, `{url}`, `{minutes}`, `{state}`, `{lock}`, `{devices}`, `{id}`, `{date}`, `{count}`, `{key}`.

## Сборка из исходников

Обычная сборка через Gradle (нужен доступ к `repo.papermc.io`):

```bash
cd Void2FA
gradle build --no-daemon
# результат: build/libs/Void2FA-1.3.5.jar
```

Требуется JDK 25. Зависимость: `io.papermc.paper:paper-api:26.2.build.+`.

> Готовый `.jar` для 1.3.5 собирается CI (артефакт `Void2FA-plugin`). В `release/` лежит старый 1.0.0.

## Заметки о безопасности

- Код подтверждения — второй фактор: он приходит только в привязанный Telegram.
- Кнопки подтверждения проверяют, что нажавший — владелец привязанного аккаунта.
- Привязка и ввод кода работают только в **личных** чатах с ботом.
- Отвязать аккаунт во время незавершённого входа нельзя (защита от обхода).
- В embedded токен хранится только в локальном `config.yml`; в external — `BOT_TOKEN`/секрет-файл бота.
- External bridge подписан HMAC в обе стороны; удалённое размещение требует HTTPS/туннеля.
- `lockdown-if-unavailable: false` по умолчанию пропускает новые входы при недоступности бота; выбери политику осознанно.
- Для доверенных админов выдай `void2fa.bypass`, чтобы не блокировать их при сбое бота.
- Доверенное устройство — это IP клиента, а не аппаратный идентификатор: при смене IP нужно подтвердить вход заново.
- Блокировка аккаунта сильнее `void2fa.bypass`: заблокированный аккаунт не пустит никого до `/unlock`.
- `/kick` и `/revoke` в Telegram выполняются только для аккаунта, привязанного к этому Telegram, и только в личном чате.
- `/revoke` не блокирует аккаунт навсегда: он убирает доверенные IP и сессию, чтобы следующий вход прошёл обычную проверку 2FA.
