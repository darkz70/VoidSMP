# Подключение своего Telegram-бота к VoidSMP

**Сохранено для следующего этапа.** Здесь — тексты для BotFather, сообщения бота, инструкция подключения и ТЗ для отдельного бота на твоём сервере.

Сейчас Telegram-аккаунт бота не создан, токен не указан, к твоему серверу никто не подключался. Этот документ ничего не запускает и не изменяет в работе сервера.

## 1. Что уже есть

- Плагин `Void2FA` с исходниками и JAR: [`release/Void2FA-1.0.0.jar`](release/Void2FA-1.0.0.jar).
- Логика привязки аккаунта, кодов подтверждения и кнопок «Подтвердить / Отклонить».
- Telegram-клиент **внутри плагина**: `TelegramBot.java` и `TelegramUpdateHandler.java`.
- Все изменяемые сообщения: [`src/main/resources/config.yml`](src/main/resources/config.yml), секция `messages`.

**Исторический текст этапа 1.0.0. Обновление 1.3.5:** отдельный исполняемый сервис подготовлен в [`bot/`](bot/), инструкция — [`BOT_DEPLOY.md`](BOT_DEPLOY.md). Разделы ниже сохранены как исходные тексты и требования; утверждения об отсутствии моста относятся к JAR 1.0.0. Для текущей версии достаточно создать Telegram-аккаунт через BotFather и указать его токен в настройках плагина. Если бот будет отдельной программой на твоём сервере, понадобится интеграция, описанная в разделе 7.

## 2. Сохранённые тексты для BotFather

Это предложения для оформления. Доступность username нужно проверить при создании.

**Имя бота:**

```text
VoidSMP | 2FA
```

**Username:** выбери свой свободный username, заканчивающийся на `bot`. Он понадобится игрокам для поиска бота.

**Описание профиля — `/setdescription`:**

```text
Бот защиты аккаунтов VoidSMP. Привязка Telegram и подтверждение входа в Minecraft.

Начни с /start. Для привязки получи код в игре командой /2fa link.
```

**Короткое описание — `/setshortdescription`:**

```text
Защита аккаунта VoidSMP: привязка Telegram и подтверждение входа.
```

**Меню команд — `/setcommands`:** бот публикует меню сам при запуске (`setMyCommands`),
поэтому этот шаг не обязателен. Если хочешь задать меню вручную, отправь BotFather следующие строки:

```text
start - Приветствие и инструкция
link - Привязать аккаунт по коду из игры
status - Проверить привязку и статус 2FA
unlink - Отвязать аккаунт
lock - Заблокировать аккаунт
unlock - Разблокировать аккаунт
devices - Доверенные устройства
untrust - Убрать устройство: id или all
kick - Завершить текущий вход
revoke - Убрать все устройства и кикнуть
help - Все команды бота
```

Эти команды соответствуют текущему обработчику плагина. Меню BotFather только показывает кнопки: обработка команд должна оставаться в плагине или будущем сервисе бота.

## 3. Подключение текущего плагина — когда будешь готов

Ничего не нужно делать сейчас. Сохрани порядок на будущее:

1. Создай **своего** бота через [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. На своём Minecraft-сервере установи JAR в `plugins/` и запусти сервер, чтобы появился `plugins/Void2FA/config.yml`.
3. Открой **локальный конфиг на сервере**, не файл в публичном репозитории. Замени пустое значение `telegram.bot-token` своим токеном:

   ```yaml
   telegram:
     bot-token: "ЗАМЕНИ_НА_ТОКЕН_СВОЕГО_БОТА"
     bot-username: ""
   ```

   Строка выше — шаблон, не рабочий токен. Пока подключения не нужны, оставь `bot-token: ""`. Поле `bot-username` необязательно: после подключения плагин получает username через Telegram API.
4. Выполни `/2faadmin reload` с правами `void2fa.admin` либо перезапусти сервер.
5. Дождись сообщения в консоли: `Telegram-бот подключён: @имя_бота`.
6. В игре выполни `/2fa link`. Открой своего бота и отправь `/link КОД_ИЗ_ИГРЫ` либо используй ссылку из сообщения плагина.
7. После успешной привязки зайди на сервер повторно. Проверь код `/login КОД` и оба действия кнопками: подтверждение и отклонение.

По умолчанию режим `opt-in`: защита применяется к привязавшим Telegram игрокам с включённой 2FA. Режим `required` требует привязки от остальных игроков без `void2fa.bypass`.

**Не передавай токен в чат, скриншотах, issue или коммитах Git.** Здесь намеренно нет настоящего токена.

## 4. Сохранённые сообщения бота

Ниже — человекочитаемая копия текущих текстов. Источник для изменения сообщений — `config.yml`; после правок на сервере применяется `/2faadmin reload`.

Фигурные поля вроде `{player}` заменяет программа. Не заменяй их настоящим токеном BotFather.

```text
/lock — заблокировать аккаунт
/unlock — разблокировать аккаунт
/devices — доверенные устройства
/untrust <id|all> — убрать устройство
/kick — завершить текущий вход
/revoke — убрать все устройства и завершить вход
/help — помощь
```

**Успешно — `tg-link-success`:**

```text

```

```text

```

### Поля сообщений

| Поле | Значение |
|---|---|

| `{code}` | Одноразовый код подтверждения, не токен BotFather |

## 5. Формат обмена, который уже использует плагин

Это описание текущей реализации, **не адрес готового HTTP API**.

- Привязка: `/link КОД` в личном чате.
- Deep link: `/start LINK_КОД`; ссылка имеет вид `https://t.me/USERNAME?start=LINK_КОД`.
- Статус: `/status`; отвязка: `/unlink`; помощь: `/help`.
- Блокировка аккаунта: `/lock`, `/unlock`; доверенные устройства: `/devices`, `/untrust <id|all>`.
- Подтверждение кнопкой: `callback_data = v2fa:ok:AUTH_ID`.
- Отклонение кнопкой: `callback_data = v2fa:no:AUTH_ID`.
- `AUTH_ID` — идентификатор текущей попытки входа, не UUID игрока и не токен BotFather.
- Привязка и команды принимаются только из личных чатов. Нажатие кнопки проверяется по Telegram user ID и привязке текущей попытки.
- Коды и решение о входе создаёт/проверяет плагин. Бот не должен самостоятельно объявлять игрока авторизованным.

Используемые методы Telegram Bot API: `getMe`, `deleteWebhook`, `getUpdates`, `sendMessage`, `editMessageText`, `answerCallbackQuery`.

## 6. Если бот будет отдельной программой на твоём сервере

**В текущем JAR нет HTTP/WebSocket-моста для внешнего бота.** Один только токен не соединяет отдельную программу с состоянием игроков в Minecraft.

Текущий плагин сам вызывает `getUpdates`, а при запуске вызывает `deleteWebhook`. Поэтому:

- не запускай второй `getUpdates` с тем же токеном параллельно с плагином;
- не указывай в текущем плагине токен работающего бота с webhook: запуск плагина удалит webhook и начнёт забирать обновления сам;
- сначала добавь явную интеграцию между отдельным ботом и плагином либо используй только встроенный вариант из раздела 3.

Для раздельного размещения нужен адаптер: плагин передаёт события попытки входа/привязки, бот отправляет сообщения, а плагин получает проверенные результаты команд и нажатий. Сетевой мост должен быть аутентифицирован; нельзя открывать неаутентифицированный endpoint «разрешить вход игроку».

## 7. Готовое ТЗ для следующего этапа

Сохрани этот текст или используй его как задание разработчику/агенту, когда решишь делать отдельного бота:

```text
Мне нужен отдельный Telegram-бот для моего Minecraft-сервера VoidSMP.
Бот будет размещён на моей инфраструктуре. Сейчас не подключайся к моему
серверу: сначала подготовь исходники, тесты и инструкцию развёртывания.

Сервер: Paper 26.2, Java 25.
Существующий проект: Void2FA/ в репозитории darkz70/VoidSMP.
Тексты и сценарии: Void2FA/BOT_SETUP.md.
Текущие сообщения: Void2FA/src/main/resources/config.yml.

Важно: текущий плагин уже содержит Telegram long polling.
Не создавай второй независимый опрос того же токена. Раздели Telegram-транспорт
и логику 2FA, затем реализуй безопасный мост между плагином и отдельным ботом.
Документируй реальный протокол; не называй несуществующие endpoints готовыми.

Сохрани сценарии:
1. /2fa link в игре -> одноразовый код -> /link КОД или /start LINK_КОД в боте.
2. Вход игрока -> запрос в Telegram -> код /login или кнопки Подтвердить/Отклонить.
3. /status, /unlink, /help.
4. Отказ, истечение срока, выход игрока и повторное использование старого события.

Коды и итоговую проверку выполняет плагин. Проверяй владельца привязки,
срок и одноразовость события. Не доверяй произвольному Minecraft UUID от клиента.
Обработка только в личном чате; сетевой мост с аутентификацией и защитой от повторов.
Токен бота — в переменной окружения BOT_TOKEN или секрет-хранилище, не в Git.
Не логируй токены и коды. Не запрашивай пароль Minecraft и токен в переписке.

Сначала покажи план изменений и список файлов. После реализации добавь тесты
без настоящего Telegram-токена и инструкцию запуска на моём сервере.
Не изменяй рабочий сервер без отдельного разрешения.
```

## 8. Что проверить перед включением на рабочем сервере

- [ ] Сначала испытать плагин на тестовой копии сервера.
- [ ] Используется только твой бот и только один способ получения обновлений.
- [ ] Токен не попал в Git, логи или переписку.
- [ ] `/2fa link`, `/status`, `/unlink` работают в личном чате.
- [ ] Верный код подтверждает вход, неверный — нет.
- [ ] Кнопка «Отклонить» завершает попытку входа.
- [ ] Просроченные коды и повторные нажатия не открывают доступ.
- [ ] Настроен доступ администратора для восстановления привязки через `/2faadmin reset НИК`.
- [ ] Осознанно выбран режим при недоступности бота: сейчас `lockdown-if-unavailable: false`, то есть при отсутствии готового бота плагин не блокирует вход.
