# VoidFastBoats

Серверный плагин для **Paper 26.2, Java 25**. Ускоряет лодки и плоты (включая варианты с сундуком) на поверхности воды, пока водитель нажимает вперёд или назад. У пассажира управление отсутствует. По умолчанию ускорение доступно всем, множитель — **2**.

## Сборка и установка

Требуются JDK 25 и Gradle 9.1 или новее:

```sh
gradle clean build
```

Результат: `build/libs/VoidFastBoats-1.0.3.jar`. Поместите его в `plugins/` сервера Paper 26.2 и перезапустите сервер. Конфиг появится в `plugins/VoidFastBoats/config.yml`.

Также добавлена GitHub Actions-сборка: после отправки изменений в GitHub успешный запуск **Build plugin** выдаст артефакт **VoidFastBoats** с JAR. Зависимость `26.2.+` выбирает доступную сборку API ветки 26.2 (новый формат версий Paper); для воспроизводимой сборки можно закрепить конкретную опубликованную версию.

## Команды

Администратор (OP или право `voidfastboats.admin`):

| Команда | Действие |
| --- | --- |
| `/boatspeed` | Текущие настройки |
| `/boatspeed 2` | Включить ускорение, выставить множитель 2 и лимит 0.8 блока/тик, сохранить |
| `/boatspeed 5` | Включить множитель 5, лимит 2 блока/тик |
| `/boatspeed 20` | Максимальный режим: множитель 20, лимит 8 блоков/тик |
| `/boatspeed 1` | Не вмешиваться в обычную физику |
| `/boatspeed on` | Включить ускорение |
| `/boatspeed off` | Выключить ускорение |
| `/boatspeed debug` | Версия, текущая причина отсутствия ускорения и последняя попытка перемещения |
| `/boatspeed reload` | Перечитать конфиг без перезапуска сервера |

Допустимый множитель: **1–20**. Числовая команда сразу включает плагин, устанавливает множитель и соответствующий лимит `max-speed = 0.4 × множитель`, сохраняет все три настройки. Вручную редактировать конфиг не нужно. Настройка общая для всех водителей с правом использования в разрешённых мирах. При множителе 1 плагин не вмешивается в физику. Команды `on`/`off` только переключают ускорение, не меняя множитель и лимит. Право `voidfastboats.use` по умолчанию есть у всех; его можно отозвать через менеджер прав.

После обновления JAR перезапустите сервер и выполните `/boatspeed 20`: это обновит лимит даже в уже существующем конфиге. Максимальный предел — 160 блоков/сек при 20 TPS, не гарантированная фактическая скорость.

## Настройки

- `enabled`: включение ускорения.
- `multiplier`: коэффициент дополнительного перемещения, а не точное отношение измеренных скоростей. При 1 плагин не меняет движение.
- `max-speed`: бюджет суммарного горизонтального перемещения **при ускорении**, 0.1–8 блока/тик, по умолчанию 1.2. При 20 TPS это 24 блока/сек. Добавка равна минимуму из `обычное смещение × (multiplier − 1)` и оставшегося бюджета `max-speed − обычное смещение`. Если бюджет исчерпан, добавка равна нулю: плагин не тормозит обычное движение.
- `worlds`: список имён миров; `[]` означает все миры.

Ускорение не применяется на суше, льду, в воздухе, под водой и к пустым лодкам. При отпускании клавиш остаётся обычное торможение; `off` не останавливает лодку мгновенно. Плагин больше не записывает `velocity`: версия 1.0.2 добавляет горизонтальное перемещение через синхронную телепортацию лодки с пассажирами (Paper 26.2 сохраняет их по умолчанию). Предыдущее собственное перемещение исключается из следующего расчёта. Перед добавкой проверяется объём пути лодки и пассажиров на блоки, сущности, границу мира и незагруженные чанки. Проверка консервативная: у диагональных препятствий добавка может отключаться заранее. Чанки принудительно не загружаются. Античит может ограничивать ускорение — проверяйте его настройки на тестовом сервере.

## Проверка перед использованием

Исходники API сверены с веткой Paper `ver/26.2` (Java 25, API 26.2). В среде разработки нет Java/Gradle и доступа к Maven-репозиторию Paper, поэтому **сборка, JUnit-тесты и игровая проверка здесь не выполнялись**. Сборка версии 1.0.2 в GitHub Actions прошла успешно; это не игровая проверка. JAR новых версий берите из соответствующего успешного запуска Actions. Лодки частично управляются клиентом; эффективность дополнительного перемещения, сохранение пассажиров и отсутствие рывков необходимо подтвердить на реальном сервере с клиентом 26.2, особенно при задержке сети.

После сборки на отдельном Paper 26.2 проверьте:

1. Загрузку плагина без ошибок, создание конфига и команду из консоли.
2. Обычную лодку, лодку с сундуком и бамбуковый плот: вперёд, назад, повороты, отпускание клавиш и столкновение с берегом.
3. Сравнение времени на одинаковом участке воды при множителях 1, 2, 3; отсутствие бесконечного разгона.
4. Отсутствие ускорения от ввода второго пассажира, на льду и при отозванном праве.
5. `on`, `off`, `reload`, перезапуск, фильтр миров; отклонение `NaN`, бесконечности и чисел вне диапазона.
6. Выход водителя, разрушение лодки и выгрузку чанка без ошибок в консоли.

`gradle test` проверяет дополнительное перемещение, отсутствие торможения при низком лимите, игнорирование скачков позиции и проверку числовых значений; эти тесты не заменяют игровую проверку.

## Исправление 1.0.2: множитель 5 тормозил лодку

Старая реализация записывала серверную `velocity` каждый тик. У лодки с водителем движение рассчитывает клиент, поэтому запись могла конфликтовать с ним; по пользовательскому замеру множитель 1 давал 8 блоков/сек, а 5 — всего 4. Этот механизм удалён, а не усилен новым коэффициентом.

После замены JAR (оставьте только одну версию плагина) полностью перезапустите сервер. На свободной воде сравните `/boatspeed 1` и `/boatspeed 5` на одном участке. Затем выполните `/boatspeed debug`: команда показывает и последнюю попытку добавки, чтобы открытие чата и отпускание клавиши не стирали результат. Отправьте обе строки диагностики, если ускорения нет. Математический тест для 8 блоков/сек ожидает дополнительное смещение 1.6 блока/тик при множителе 5, **но это не измерение скорости на настоящем сервере**. Сетевые коррекции, телепортации и античит всё ещё требуют игровой проверки; новая реализация пока экспериментальная.

## Версия 1.0.3: множитель до 20

Команда `/boatspeed 20` включает ускорение, сохраняет множитель 20 и лимит 8 блоков/тик. Поддерживаются также дробные числа от 1 до 20. Старые конфиги совместимы; значение по умолчанию остаётся 2. После обновления JAR нужен полный перезапуск сервера.

160 блоков/сек при 20 TPS — расчётный бюджет, не обещанная измеренная скорость. Начинайте с 5 и 10: при 20 выше риск рывков, коррекций античита и остановок добавки на границе загруженных чанков. Проверка всего пути на препятствия сохранена и на больших расстояниях требует больше серверного времени.
