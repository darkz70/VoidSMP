# VoidFastBoats

Серверный плагин **Paper 26.2 / Java 25**, версия **1.0.6**. Обычные лодки, плоты и варианты с сундуком; управление скоростью командами. Клиентских модов не требует.

**Для ускорения теперь нужен PacketEvents 2.13.0 или новее, поддерживающий Paper 26.2.** В присланном пользователем логе уже есть `packetevents (2.13.0)`. ProtocolLib не заменяет PacketEvents. При отсутствии зависимости разгон не работает, но команды диагностики остаются доступны. PacketEvents не встраивается в JAR, не загружается плагином автоматически и не инициализируется повторно.

## Установка

1. Полностью остановите сервер.
2. Уберите старый JAR VoidFastBoats, оставьте только `VoidFastBoats-1.0.6.jar` в `plugins/`.
3. Убедитесь, что PacketEvents установлен и включается без ошибок.
4. Запустите сервер, выполните в консоли `boatdebug`. В ответе должны быть **1.0.6** и транспорт **PacketEvents / ENTITY_VELOCITY**.
5. В игре начните с `/boatspeed 2`, не с 1000.

Старый `plugins/VoidFastBoats/config.yml` совместим. Не нужно удалять настройки миров или прав. Для самостоятельной сборки требуются JDK 25 и Gradle 9.1+: `gradle clean build`. Результат — `build/libs/VoidFastBoats-1.0.6.jar`. GitHub Actions публикует артефакт **VoidFastBoats**. API Paper выбирается из ветки `26.2.+`; PacketEvents API закреплён на `2.13.0`.

## Команды

Нужны OP или право `voidfastboats.admin`:

| Команда | Действие |
| --- | --- |
| `/boatspeed` | Настройки |
| `/boatspeed 2` | Включить разгон и сохранить множитель 2 |
| `/boatspeed 2.5` | Дробный множитель |
| `/boatspeed 80` | Множитель 80; верхнего предела команды нет |
| `/boatspeed 1` | Обычная физика, пакеты ускорения не отправляются |
| `/boatspeed off` / `/boatspeed on` | Выключить / включить разгон |
| `/boatspeed reload` | Перечитать настройки и повторно проверить транспорт |
| `/boatdebug` | Версия, конфиг, транспорт и диагностика своего движения |
| `/boatdebug Ник` | Диагностика указанного игрока — работает и из консоли |
| `/boatspeed debug Ник` | То же через подкоманду |

В консоли команды вводятся **без `/`**. `boatdebug` без ника в консоли показывает игроков онлайн. Например:

```text
boatdebug verte_vakala
```

При конфликте имён: `voidfastboats:boatdebug verte_vakala`.

Диагностика показывает причину остановки разгона, измеренную скорость по реальному времени, скорость пакета, ID лодки, время последней попытки и количество пакетов за подключение. **«В очереди отправки» не означает подтверждённое применение клиентом.** Открытие чата не стирает последнюю попытку. Статистика удаляется при выходе игрока; в файлы не пишется.

## Что изменено в 1.0.6

В предыдущих версиях множитель 1000 по пользовательскому замеру не ускорял лодку: 150 блоков за 17 с вместо 16,7 с при множителе 1. Телепортации вызывали рывки. Большие числа в команде сами по себе не решали проблему.

- Удалён вызов Bukkit `setVelocity`. Он меняет серверный `deltaMovement`; серверная обработка лодки может обнулить его до передачи клиенту.
- Отправляется **`ENTITY_VELOCITY` напрямую клиенту водителя для ID лодки**, через PacketEvents. Серверное поле скорости не меняется. Остальные игроки получают обычные обновления позиции сервера. Пакеты идут через обычный путь PacketEvents, не обходят слушателей других плагинов.
- Телепортаций, высадки/повторной посадки пассажиров нет.
- Скорость измеряется по двум тикам движения, а не по серверному `getVelocity`. В диагностике блоки/сек учитывают реальное прошедшее время.
- Импульс компенсирует модель сопротивления воды: в каждом тике `v = 0.9 × v + тяга`. Целевая средняя скорость повышается постепенно, максимум на 0.08 блока/тик за один двухтиковый цикл. Это устраняет ограничение старого расчёта, в котором постоянную маленькую добавку поглощало сопротивление.
- Переключение водителя, мира и телепортации сбрасывают образцы. Скачки высоты и длительные задержки пропускаются. Пакеты не отправляются стоящей лодке, при отпускании клавиш или при движении против выбранного направления гребли.
- Перед импульсом проверяется ближайший участок пути на препятствия, сущности, незагруженные чанки и границу мира. Проверка ограничена 16 блоками для ограничения затрат CPU. Она не заменяет ванильную физику столкновений.
- Отсутствующая/несовместимая зависимость имеет явное сообщение. Отсоединение одного клиента не выключает ускорение остальных. При неожиданной ошибке транспорта отправка останавливается с сообщением в лог, а не повторяет исключение каждый тик.

## Настройки и ограничения

- `enabled`: включение разгона.
- `multiplier`: конечное число >= 1 без верхнего предела команды; по умолчанию 2. Целевая скорость модели — `0.4 × multiplier` блока/тик. При 1 плагин не вмешивается.
- `worlds`: точные имена миров; `[]` — все миры.
- Старый `max-speed` игнорируется и удаляется при сохранении через команду.
- `voidfastboats.use` по умолчанию выдан всем; его можно отозвать менеджером прав.

Разгон только на поверхности воды, только по вводу первого пассажира-водителя. Не действует на льду, суше, под водой и без водителя. `off` не тормозит мгновенно. Невалидный конфиг отклоняется с указанием поля; команды остаются доступны. При неудачном reload прежние рабочие настройки остаются в памяти. Испорченный файл не перезаписывается командами настройки до исправления и успешного reload.

Проверки движения Paper, античит, столкновения и загрузка чанков **не отключаются**. Старые клиенты до протокола 1.21.9 не поддерживаются этим транспортом. Неограниченное числовое поле — **не обещание неограниченной фактической скорости**. Особенно большие значения могут вызвать коррекции, рывки, ошибки движения или нагрузку на сервер.

## Что проверено, а что нет

Автотесты проверяют:
- диапазоны и отсутствие прежнего потолка множителя;
- постепенный разгон и компенсацию сопротивления в упрощённой математической модели;
- создание пакета с ID лодки и передачу именно водителю через замоканный PacketEvents;
- отсутствие Bukkit `setVelocity` в транспорте;
- ошибки отсутствующей/старой зависимости, неподдерживаемого клиента, соединения и нечислового вектора.

**Тест с настоящим Minecraft-клиентом не выполнен.** Модель сопротивления и замоканный транспорт не проверяют сетевую доставку, плавность, интерполяцию, античит и реальную скорость. Нельзя считать проблему окончательно решённой только по успешной сборке.

Проверка на сервере: один и тот же прямой участок 150 блоков, сначала `/boatspeed 1`, затем `/boatspeed 2` после небольшого разгона. Второй заезд должен быть заметно быстрее без рывков, иначе исправление не принимается. Во время заезда можно вызвать `boatdebug Ник` из консоли, не отпуская клавишу игрока. Затем проверить повороты, задний ход, берег, второго пассажира, сундук, плот, выход/разрушение лодки, `off`, фильтр миров и перезапуск. Значения 5 и выше проверять только после успешного теста на 2.
