# VoidFastBoats

Экспериментальный **серверный плагин Paper 26.2 / Java 25** для ускорения лодок и плотов, в том числе с сундуком. Клиентские моды и ProtocolLib не требуются. Доступ к ускорению по умолчанию есть у всех; множитель по умолчанию — 2.

## Установка и обновление

С JDK 25 и Gradle 9.1+:

```sh
gradle clean build
```

Результат: `build/libs/VoidFastBoats-1.0.5.jar`. Также JAR доступен в артефакте **VoidFastBoats** соответствующего успешного запуска GitHub Actions. Зависимость `paper-api:26.2.+` выбирает опубликованную сборку API ветки 26.2; для воспроизводимости можно закрепить конкретную версию.

Остановите сервер, уберите старый JAR VoidFastBoats, положите новый в `plugins/` и запустите сервер. Конфиг `plugins/VoidFastBoats/config.yml` сохраняется: удалять его не нужно. Не оставляйте несколько версий JAR одновременно. Начните проверку с `/boatspeed 2`, а не с 20.

## Команды

Нужны OP или `voidfastboats.admin`:

| Команда | Действие |
| --- | --- |
| `/boatspeed` | Текущие настройки |
| `/boatspeed 2` | Включить разгон, установить множитель 2 и целевой предел 0.8 блока/тик |
| `/boatspeed 5` | Множитель 5, целевой предел 2 блока/тик |
| `/boatspeed 20` | Множитель 20, целевая скорость 8 блоков/тик |
| `/boatspeed 80` | Множитель 80, целевая скорость 32 блока/тик |
| `/boatspeed 1` | Обычная физика без вмешательства плагина |
| `/boatspeed on` / `/boatspeed off` | Включить / выключить разгон |
| `/boatspeed reload` | Перечитать конфиг |
| `/boatspeed debug` | Версия, текущий статус и последний результат попытки разгона |

Допускается **любое конечное число от 1 без верхнего предела**, включая дробные: `/boatspeed 2.5`. Числовая команда включает разгон, задаёт целевую скорость `0.4 × множитель` и сохраняет настройки. Это общая настройка для всех водителей с правом `voidfastboats.use` в разрешённых мирах. `on` и `off` не меняют множитель. Отключение не останавливает лодку мгновенно.

## Изменение механизма в 1.0.4

В 1.0.0–1.0.1 горизонтальная скорость вычислялась из серверной `velocity`, которая может не отражать движение управляемой клиентом лодки. Пользователь сообщил о снижении скорости с 8 до 4 блоков/сек. Версии 1.0.2–1.0.3 вместо этого телепортировали лодку; пользователь сообщил о рывках.

**В 1.0.4 телепортации полностью удалены.** Новый экспериментальный алгоритм:

- Замеряет фактическое горизонтальное перемещение между позициями лодки за два серверных тика.
- На основе этого замера отправляет импульс через `setVelocity`, а не умножает устаревшую серверную горизонтальную скорость.
- Повышает запрошенную скорость не более чем на 0.08 блока/тик за один двухтиковый цикл. Большой множитель не вызывает мгновенный скачок до максимума.
- Сохраняет вертикальную скорость. Не ускоряет стоящую лодку, при отпускании клавиш, смене направления до начала движения в новую сторону.
- Перед импульсом консервативно проверяет объём пути лодки и пассажиров на препятствия, сущности, незагруженные чанки и границу мира. Проверка только разрешает или запрещает импульс; фактическое движение и столкновения остаются ванильными.
- Работает только на поверхности воды и только по вводу первого пассажира — водителя.

Это **не подтверждённое исправление плавности в игре**. Клиент, задержка сети, пакетные обновления движения и античит могут игнорировать или корректировать импульсы. Двухтиковый замер — оценка скорости, не точный спидометр. Плагин не отключает античит и серверные проверки движения. Верхний предел множителя снят в 1.0.5, но ни плавность, ни достижение выбранной скорости не гарантируются. Проверка препятствий ограничена ближайшими 16 блоками, чтобы огромные значения команды не приводили к неограниченному сканированию мира. Это ограничение объёма проверки, а не скорости.

## Конфиг

- `enabled`: включение разгона.
- `multiplier`: любое конечное число >= 1; при 1 плагин не вмешивается в движение.
- `max-speed`: устаревшее поле, полностью игнорируется и удаляется при сохранении через команду. Цель разгона теперь определяется только множителем. Если скорость уже выше цели, плагин не тормозит лодку.
- `worlds`: список точных имён миров; `[]` означает все миры.

Старые конфиги совместимы. Настройки числовой команды сохраняются после перезапуска. Неверный тип или значение в конфиге отклоняется с указанием поля. При ошибке на старте разгон выключен, но команды диагностики и `/boatspeed reload` остаются доступны. Ошибка при reload сохраняет прежние рабочие настройки в памяти; `/boatspeed off` доступна даже при ошибке и не перезаписывает испорченный файл. Исправьте конфиг и выполните reload, чтобы снова менять скорость.

## Проверка

Локально Java/Gradle отсутствуют. GitHub Actions запускает `gradle clean build`, включая JUnit. Игровая проверка с реальным клиентом 26.2 не выполнена. Математические тесты проверяют границы, ограничение каждого импульса и отсутствие замены измеренной скорости меньшей серверной величиной; они не моделируют клиентскую физику или сеть.

На тестовом сервере:

1. Сравните время на одном прямом водном участке при `/boatspeed 1`, `2`, затем `5`.
2. Проверьте повороты, задний ход, отпускание клавиш, берег, второго пассажира, лодку с сундуком и плот.
3. Проверьте отсутствие разгона на льду, под водой, без права `voidfastboats.use` и в исключённом мире.
4. Проверьте выход из лодки, разрушение, смену мира, `off`, `reload`, перезапуск и сохранение настроек.
5. После заплыва выполните `/boatspeed debug`. Последний результат сохраняется при открытии чата. При проблемах сообщите вывод, версию Paper, клиент (Java/Bedrock через Geyser), античит и пинг.
6. Только после проверки на малых значениях пробуйте 10–20. При рывках верните `/boatspeed 1`.

## Диагностика загруженного лога

В `2026-10-11-9.log` в 13:24:14 версия 1.0.3 отклонила `config.yml` и отключилась. Сообщения `plugin is disabled` при `/boatspeed 80` и `/boatspeed 20` — следствие этого отключения, а не первопричина. Точное поле старая версия не записала; содержимое конфига в логе отсутствует. В 1.0.5 добавлена диагностика поля и убраны прежние верхние границы `multiplier`/`max-speed`. Это не исправляет произвольную ошибку YAML автоматически.
