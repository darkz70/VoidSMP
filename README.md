# VoidFastBoats

Серверный плагин для **Paper 26.2, Java 25**. Ускоряет лодки и плоты (включая варианты с сундуком) на поверхности воды, пока водитель нажимает вперёд или назад. У пассажира управление отсутствует. По умолчанию ускорение доступно всем, множитель — **2**.

## Сборка и установка

Требуются JDK 25 и Gradle 9.1 или новее:

```sh
gradle clean build
```

Результат: `build/libs/VoidFastBoats-1.0.1.jar`. Поместите его в `plugins/` сервера Paper 26.2 и перезапустите сервер. Конфиг появится в `plugins/VoidFastBoats/config.yml`.

Также добавлена GitHub Actions-сборка: после отправки изменений в GitHub успешный запуск **Build plugin** выдаст артефакт **VoidFastBoats** с JAR. Зависимость `26.2.+` выбирает доступную сборку API ветки 26.2 (новый формат версий Paper); для воспроизводимой сборки можно закрепить конкретную опубликованную версию.

## Команды

Администратор (OP или право `voidfastboats.admin`):

| Команда | Действие |
| --- | --- |
| `/boatspeed` | Текущие настройки |
| `/boatspeed 2` | Включить ускорение, выставить множитель 2 и лимит 0.8 блока/тик, сохранить |
| `/boatspeed 5` | Включить максимальный режим: множитель 5, лимит 2 блока/тик |
| `/boatspeed 1` | Не вмешиваться в обычную физику |
| `/boatspeed on` | Включить ускорение |
| `/boatspeed off` | Выключить ускорение |
| `/boatspeed reload` | Перечитать конфиг без перезапуска сервера |

Допустимый множитель: **1–5**. Числовая команда сразу включает плагин, устанавливает множитель и соответствующий лимит `max-speed = 0.4 × множитель`, сохраняет все три настройки. Вручную редактировать конфиг не нужно. Настройка общая для всех водителей с правом использования в разрешённых мирах. При множителе 1 плагин не вмешивается в физику. Команды `on`/`off` только переключают ускорение, не меняя множитель и лимит. Право `voidfastboats.use` по умолчанию есть у всех; его можно отозвать через менеджер прав.

После обновления JAR перезапустите сервер и выполните `/boatspeed 5`: это обновит лимит даже в уже существующем конфиге. Максимальный предел — 40 блоков/сек при 20 TPS, не гарантированная фактическая скорость.

## Настройки

- `enabled`: включение ускорения.
- `multiplier`: коэффициент дополнительной тяги и целевой скорости, а не точное отношение измеренных скоростей. При 1 плагин не меняет движение.
- `max-speed`: верхний предел горизонтальной скорости **при приложении тяги**, 0.1–2 блока/тик, по умолчанию 1.2. При 20 TPS это 24 блока/сек. Целевой предел — минимум из `0.4 × multiplier` и `max-speed`.
- `worlds`: список имён миров; `[]` означает все миры.

Ускорение не применяется на суше, льду, в воздухе, под водой и к пустым лодкам. При отпускании клавиш остаётся обычное торможение; `off` не останавливает лодку мгновенно. Вертикальная скорость не меняется. Плагин не телепортирует лодки и не загружает чанки принудительно. Античит может ограничивать ускорение — проверяйте его настройки на тестовом сервере.

## Проверка перед использованием

Исходники API сверены с веткой Paper `ver/26.2` (Java 25, API 26.2). В среде разработки нет Java/Gradle и доступа к Maven-репозиторию Paper, поэтому **сборка, JUnit-тесты и игровая проверка здесь не выполнялись**. Готовый проверенный JAR не приложен. Лодки частично управляются клиентом; эффективность `setVelocity` и отсутствие рывков необходимо подтвердить на реальном сервере с клиентом 26.2, особенно при задержке сети.

После сборки на отдельном Paper 26.2 проверьте:

1. Загрузку плагина без ошибок, создание конфига и команду из консоли.
2. Обычную лодку, лодку с сундуком и бамбуковый плот: вперёд, назад, повороты, отпускание клавиш и столкновение с берегом.
3. Сравнение времени на одинаковом участке воды при множителях 1, 2, 3; отсутствие бесконечного разгона.
4. Отсутствие ускорения от ввода второго пассажира, на льду и при отозванном праве.
5. `on`, `off`, `reload`, перезапуск, фильтр миров; отклонение `NaN`, бесконечности и чисел вне диапазона.
6. Выход водителя, разрушение лодки и выгрузку чанка без ошибок в консоли.

`gradle test` проверяет вычисление тяги, направление, ограничения скорости и проверку числовых значений; эти тесты не заменяют игровую проверку.
