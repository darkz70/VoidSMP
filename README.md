# VoidSMP

Плагин для **Paper 26.2** (Minecraft 26.2, Java 25).

## Что делает

1. **Лут обычных хранилищ (Vault).** Обычным хранилищам в испытательных камерах
   подменяется лут-таблица на свою: за одно открытие выпадает **ровно 2 предмета**
   по таблице шансов ниже. Механика ключей — полностью ванильная (нужен ключ
   от испытаний, он тратится как обычно).
2. **Жуткие (синие / ominous) хранилища не меняются** — у них остаётся
   ванильный лут.
3. **Еженедельный сброс всех хранилищ** (включая жуткие): убирается отметка
   «игрок уже открыл», и все снова могут открыть хранилища.
   По умолчанию — **каждую пятницу в 00:00 (Europe/Warsaw)**, настраивается
   в `config.yml`. Если сервер в это время был выключен — сброс выполнится
   при следующем старте.

## Таблица лута (обычные хранилища)

За одно открытие выпадает 2 предмета, каждый бросается независимо
по шансам из `config.yml` (сумма весов = 100%):

| Предмет | Кол-во | Шанс |
|---|---:|---:|
| Губки (Sponge) | 32 | 10% |
| Осколки призмарина | 64 | 5% |
| Кристаллы призмарина | 64 | 5% |
| Золотое яблоко | 8 | 8% |
| Стрелы | 16 | 15% |
| Зелье исцеления | 1 | 5% |
| Зелье вреда | 1 | 5% |
| Хлеб | 32 | 7% |
| Алмазы | 3 | 5% |
| Алмазный блок | 1 | 2% |
| Изумрудный блок | 1 | 3% |
| Изумруды | 5 | 5% |
| Отравленные стрелы | 8 | 5% |
| Зачарованное золотое яблоко | 1 | 1% |
| Любой элемент железной брони | 1 | 9% |
| Любой элемент медной брони | 1 | 5% |
| Любое железное оружие/инструмент | 1 | 5% |

Шансы, предметы и количество за открытие меняются в `config.yml`
(папка плагина), затем `/voidsmp reload`.

## Установка

1. Скачай jar (см. «Где взять jar» ниже).
2. Положи в `plugins/` сервера **Paper 26.2**.
3. Перезапусти сервер.
4. Проверь в консоли строку `LootTable=LOADED` — значит, датапак с лутом
   загрузился. Если `MISSING` — посмотри лог и сделай `/voidsmp reload`.

Первый запуск создаёт `plugins/VoidSMP/config.yml` — там лут и расписание сброса.

## Команды

| Команда | Что делает |
|---|---|
| `/voidsmp status` | Лут-таблица, число отслеживаемых хранилищ, время следующего сброса |
| `/voidsmp reset` | Принудительный сброс прямо сейчас |
| `/voidsmp reload` | Перечитать `config.yml`, перезаписать датапак и перезагрузить ресурсы |

Права: `voidsmp.admin` (по умолчанию — только op).

## Как это устроено

- При каждом открытии/загрузке чанка плагин ставит обычному хранилищу
  лут-таблицу `voidsmp:chests/regular_vault`. Она приходит из **внутреннего
  датапака**, который плагин регистрирует сам через Paper Datapack API
  (файлы лут-таблицы генерируются из `config.yml`).
- Жутким (ominous) хранилищам лут-таблица **не ставится никогда**.
- Плагин запоминает все хранилища, которые игроки открывали
  (`tracked-vaults.txt`), а по расписанию снимает с них отметки
  «уже открыл» (`reset-state.properties`).
- Механика ключей, анимации и выдача — ванильные; плагин ничего в ней
  не меняет.

## Где взять jar

- **GitHub Releases → `voidsmp-ci`** — свежая автосборка (обновляется
  при каждом пуше).
- **Actions → последний запуск Build VoidSMP → артефакт `VoidSMP-jar`**.
- В репозитории в ветке плагина: папка `dist/` (коммитит CI).

## Сборка

Локально: `gradle build` (нужен JDK 25 и доступ к repo.papermc.io).
Чаще всего сборку делает GitHub Actions: коммит в ветку
`arena/e1e216ad-voidsmp` → workflow **Build VoidSMP** собирает jar,
прогоняет smoke-тест на настоящем Paper 26.2 (проверяет, что сервер
стартовал, таблица `LootTable=LOADED` и команда `/voidsmp status`
отвечает) и публикует релиз. Ошибки сборки CI пишет в issue
«CI failure log».
